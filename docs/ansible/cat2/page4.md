# 演習レビュー

## 1. 処理の流れの整理

ここまでの演習を振り返り、Ansibleがどのような流れで動作しているか整理します。

### Playbook実行の流れ

```
ansible-playbook コマンド実行
        │
        ▼
① インベントリを読み込む
        │  対象ホストの一覧を取得
        ▼
② Gathering Facts（情報収集）
        │  各ノードのOS・IPなどの情報を自動収集
        ▼
③ タスクを順番に実行
        │  各モジュールをノードに対して実行
        │  ・すでに望ましい状態 → ok（変更なし）
        │  ・変更が必要 → changed（変更あり）
        │  ・エラー → failed（以降のタスクは中断）
        ▼
④ PLAY RECAP（結果サマリ）
        │  ok / changed / failed の件数を表示
        ▼
        完了
```

### Gathering Factsとは

Playbookの最初に自動実行される `Gathering Facts` は、各ノードの情報を収集するステップです。

| 収集される情報の例 | 変数名 |
|------------------|--------|
| OSの種類・バージョン | `ansible_os_family` |
| IPアドレス | `ansible_default_ipv4.address` |
| メモリ量 | `ansible_memtotal_mb` |
| CPUアーキテクチャ | `ansible_architecture` |

収集した情報は後続のタスクで変数として利用できます（変数については次のChapterで学習します）。

## 2. エラー原因の分析

Playbookが失敗したときの読み方と対処法を学びます。

### エラー出力の読み方

```
TASK [nginxをインストールする] *************************************
fatal: [node1]: FAILED! => {
    "changed": false,
    "msg": "No package matching 'ngins' found available, ...installed"
}
```

| 項目 | 確認ポイント |
|------|-------------|
| **どのタスクで失敗したか** | `TASK [タスク名]` を確認 |
| **どのホストで失敗したか** | `fatal: [ホスト名]` を確認 |
| **エラーの内容** | `"msg":` の文字列を確認 |

### よくあるエラーパターン

| エラーメッセージ | 原因 | 対処法 |
|-----------------|------|--------|
| `No package matching 'xxx' found` | パッケージ名のタイポ | パッケージ名を正確に確認 |
| `UNREACHABLE` | SSH接続不可 | インベントリのIPアドレス・SSH設定を確認 |
| `Permission denied` | sudo権限が不足 | `become: true` を追加 |
| `Syntax Error` | YAMLの書き方が間違い | インデントを確認 |
| `Could not find or access 'files/xxx'` | コピー元ファイルが存在しない | ファイルのパスを確認 |

### YAML構文エラーの確認方法

Playbookを実行する前に構文チェックができます。

```bash
ansible-playbook --syntax-check -i inventory webserver.yml
```

エラーがなければ以下が表示されます。

```
playbook: webserver.yml
```

## 3. 自動化の効果を確認する

演習を通じて体験した自動化の効果を振り返ります。

### 作業時間の比較（node2台の場合）

| 作業 | 手動操作 | Ansible |
|------|----------|---------|
| パッケージインストール | 約5分（2台分） | 約1分（並列実行） |
| 設定ファイル配置 | 約5分（コピー＋確認） | 約30秒 |
| サービス起動 | 約2分 | 約30秒 |
| **合計** | **約12分** | **約2分** |

台数が増えるほど差は広がります。10台・100台になっても、Ansibleのコマンドは変わりません。

### 自動化によって得られるもの

```
① 速度
   手動12分 → Ansible2分（6倍高速）

② 正確性
   手入力ミス → ゼロ（コードが正確に実行される）

③ 再現性
   「あのサーバだけ設定が違う」問題 → 解消

④ ドキュメント性
   Playbookがそのまま構成ドキュメントになる
```

## 4. ここまでの学習まとめ

| テーマ | 学んだこと |
|--------|------------|
| **構成管理の基礎** | 手動管理の問題・Ansibleの概要・管理ノードと被管理ノード |
| **環境構築** | インストール・SSH鍵認証・インベントリ・pingモジュール |
| **Ad-hocコマンド** | `package` / `service` / `user` モジュールの操作 |
| **Playbook基礎** | YAML記法・Playbookの構造・冪等性 |
| **Playbook作成** | `copy` モジュール・Webサーバ自動構築・起動確認 |

## 演習

1. 演習で作成した `webserver.yml` を読み返し、各タスクが「なぜその順番で実行されているか」を説明してください
2. 意図的にパッケージ名を間違えて（例: `ngins`）実行し、エラーメッセージを確認してください
3. `--syntax-check` オプションを使い、Playbookの構文チェックを実行してください
4. 手動操作でWebサーバを構築した場合と比較し、Ansibleによる自動化のメリットを3つ挙げてください
